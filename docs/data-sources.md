# Data Sources

The MVP must show where each yield and TVL value came from.

## Required Metadata

Each opportunity must include:

- Source URL
- Last updated time
- Chain
- Protocol
- Asset
- Strategy type
- APY value
- APY source label
- APY composition (`base`, `base_plus_rewards`, `rewards_only`, `farming_pool`, or `unknown`)
- APY base and reward components when supplied by the same source snapshot
- Pool metadata and reward token identifiers when supplied by the same source snapshot
- TVL value
- Contract address when available
- Contract role when a verified address is shown
- Contract verification status
- Contract verification source links when manually curated
- Related reserve, token, or wrapper contracts when manually curated
- Pool reference and pool verification status
- Verification status
- Original protocol URL when available
- Protocol docs or security materials when available
- Chain explorer URL when a contract address has been verified

## Source Rules

- Prefer original protocol data or well-known public aggregators.
- Do not mix live data and demo data without labeling.
- Do not show stale values as current.
- If a value cannot be verified, mark it as unverified or remove it.
- Do not label a third-party pool id as a contract address.
- Do not add a chain explorer link unless the address, chain, proxy/version, and source path were checked.
- If a displayed address is market-level or token-level, label that role instead of calling it a pool-specific contract.
- Related contracts must show their own role and explorer URL; they do not replace the primary contract role.
- If an APY includes token rewards, farming incentives, or source-specific pool metadata, label that composition separately from the headline APY.
- Do not backfill APY base/reward components from a different snapshot timestamp. If the original reviewed snapshot did not capture the split, mark the composition as unknown.

## Freshness Rule

The frontend treats `metadata.generated_at` as the dataset timestamp.

- Fresh: generated within the last 24 hours
- Stale: older than 24 hours, invalid, missing, or unexpectedly in the future
- Fallback: shown only when `data/opportunities.json` cannot be loaded

Stale data may remain visible for local inspection, but it must be labeled as stale and refreshed before demos, public screenshots, marketing pages, investor updates, or any user-facing release.

## Current Snapshot

The current dashboard reads `data/opportunities.json` when served from the project root. The file is generated by `backend/src/strategy_engine.py` from DeFiLlama Yields:

- Data endpoint: `https://yields.llama.fi/pools`
- Human review page: `https://defillama.com/yields`
- Output file: `data/opportunities.json`

Refresh command:

```bash
cd backend
python3 src/strategy_engine.py --refresh --limit 12 --timeout 180
```

This source is useful for public market discovery, but it is still third-party aggregator data. Aethra must not present it as audited, guaranteed, complete, or directly verified by the original protocols.

## Refresh Candidate Workflow

The `Yield Refresh Candidate` GitHub Actions workflow runs daily and can also be triggered manually. It fetches a new 12-record snapshot into `data/refresh-candidate.json`, performs a strict dataset check, and uploads the candidate plus its validation report as a seven-day Actions artifact.

The workflow has read-only repository permissions and does not modify the committed dashboard dataset. A candidate must be reviewed against the source and original protocols before a maintainer promotes it through a normal commit or pull request. A failed run, validation warning, added/removed pool, or material APY/TVL move is a review signal, not permission to publish the candidate.

By default, refreshes use the committed `data/opportunities.json` as a selection baseline. If a currently reviewed DeFiLlama pool id still satisfies the source filters, the generator prefers keeping that pool in the 12-record candidate before filling open slots by TVL. This reduces churn from near-equivalent Spark/Sky surfaces and small ranking moves. It does not freeze APY, TVL, APY composition, or risk metadata; those fields still update from the current source snapshot and remain subject to comparison review.

To inspect the raw source ranking without preferring the current reviewed pool ids, use:

```bash
cd backend
python3 src/strategy_engine.py --refresh --limit 12 --timeout 180 --ignore-selection-baseline --output ../data/refresh-candidate.json
```

The artifact also includes `refresh-candidate-comparison.json`, generated with:

```bash
cd backend
python3 src/strategy_engine.py --compare-candidate --candidate ../data/refresh-candidate.json
```

The comparison report flags added records, removed records, APY moves of at least 0.5 percentage points, TVL moves of at least 10% or 50 million USD, risk-score changes, and contract/review-anchor metadata changes. These flags only tell maintainers where to review; they do not verify market data accuracy, pool safety, or audit coverage.

The generator keeps DeFiLlama pool ids as `source_pool_id` and `pool_reference`. These are aggregator identifiers, not contract addresses. If DeFiLlama does not provide a verified contract address in the snapshot, the dataset must keep `contract_address` and `explorer_url` empty and show a contract verification warning.

The generator also records DeFiLlama APY composition fields when they are present in the same fetched snapshot:

- `apy_base`: base APY reported by the source.
- `apy_reward`: token reward APY reported by the source.
- `apy_source_label`: short display label such as `Base APY`, `Base APY plus token rewards`, or `Reward or farming APY`.
- `apy_composition`: machine-readable category.
- `pool_meta`: source pool metadata, such as a farming or incentive pool label.
- `reward_tokens`: reward token identifiers supplied by the source.

These fields help distinguish base yield from reward or farming yield. They do not prove reward availability, token value, reward sustainability, liquidity, withdrawal timing, or that two same-protocol/same-asset records are economically equivalent.

The current generator also includes a small manual verification map for selected Ethereum records where official documentation and a chain explorer can be cross-checked. These entries still do not prove APY/TVL accuracy, safety, or audit coverage:

- Lido stETH: Lido/stETH token proxy
- Sky sUSDS: sUSDS ERC-4626 token and vault proxy
- Ether.fi weETH: weETH token with related eETH and Liquidity Pool contracts
- Aave V3 Ethereum WETH/USDT: market-level Aave V3 Ethereum Pool proxy shared by multiple reserves
- Spark Savings Arbitrum USDS: Arbitrum sUSDS savings token contract
- Spark Savings Ethereum USDT: Spark Vault V2 spUSDT ERC-4626 vault proxy
- SparkLend Ethereum USDS: market-level SparkLend Pool proxy shared by multiple reserves
- Maple Ethereum USDC/USDT: Syrup USDC and Syrup USDT pool contracts
- Centrifuge Base USDC / Ethereum USDS: Janus Henderson fund vault contracts

For Aave V3 Ethereum WETH/USDT, the dataset also includes related aToken and underlying reserve token addresses from the Aave tokenlist. These are additional review anchors only. They do not confirm current APY, utilization, liquidity, reserve configuration, or audit coverage.

For Ether.fi weETH, the dataset includes related eETH and Liquidity Pool contracts from the official deployed-contracts page. These are review anchors only. They do not confirm current liquidity, withdrawal timing, redemption behavior, rewards, or restaking risk.

For Spark Savings Arbitrum USDS, the manual mapping is bound to the exact DeFiLlama pool id. The pool page identifies its token as Arbitrum sUSDS, and the full address matches the `SUSDS` constant in Spark's official Arbitrum address registry. The dataset therefore labels it as an sUSDS token contract, not a Spark Vault V2 USDS vault. The related Arbitrum USDS token is a review anchor only. These fields do not confirm APY, TVL, rate propagation, bridge assumptions, redeemability, liquidity, or audit coverage.

For Spark Savings Ethereum USDT, the dataset includes the spUSDT vault proxy, USDT underlying token, and SavingsVaultIntents contract from Spark docs and the Spark Address Registry. These are review anchors only. Spark's docs state that withdrawals depend on the vault's current idle liquidity, and intent fulfillment depends on offchain infrastructure preparing liquidity; these fields do not confirm immediate liquidity, APY, TVL, or audit coverage.

For SparkLend Ethereum USDS, the dataset includes the market-level Pool proxy plus USDS spToken, debt token, and underlying token from the Spark Address Registry. These are review anchors only. They do not confirm reserve parameters, caps, oracle configuration, utilization, liquidation risk, APY, TVL, or audit coverage.

For Maple Ethereum USDC/USDT, the dataset binds manual verification to the exact DeFiLlama pool ids whose `poolMeta` values are `Syrup USDC` and `Syrup USDT`. The related PoolManager, WithdrawalManagerQueue, router, and underlying token addresses are review anchors only. They do not verify borrower credit quality, collateral status, withdrawal queue timing, APY, TVL, or audit coverage.

For Centrifuge Base USDC and Ethereum USDS, the dataset binds manual verification to the exact DeFiLlama pool ids whose `poolMeta` values identify the Janus Henderson AAA CLO Fund and Janus Henderson Treasury Fund. The related fund token and underlying asset addresses are review anchors only. They do not verify fund asset quality, issuer/legal structure, NAV calculation, redemption timing, APY, TVL, or audit coverage.

To add or refresh protocol review links on an existing snapshot without pulling fresh APY/TVL data:

```bash
cd backend
python3 src/strategy_engine.py --enrich-existing
```

Protocol links are manual metadata curated from official protocol sites, docs, security pages, or official code repositories. They are review paths only. Aethra must not treat the existence of an audit page, bug bounty, or documentation portal as proof that a displayed pool is safe or in scope for a specific audit.

## Filtering Rules

The generator currently keeps a conservative MVP subset:

- Supported chains: Ethereum, Arbitrum, Optimism, Base, Polygon
- Supported assets: USDC, USDT, DAI, USDS, sUSDS, ETH, WETH, stETH, wstETH, weETH
- Minimum TVL: 50 million USD
- APY range: 0.1% to 25%
- Source outliers are excluded
- The output prefers currently reviewed pool ids that still pass the source filters, tries to preserve chain diversity, then fills remaining slots by TVL

If a chain has no records after these filters, it is excluded rather than padded with weaker data.

## Demo Fallback

Demo fallback data is allowed for local development only. It must be labeled as demo data and must not be presented as live market data.
